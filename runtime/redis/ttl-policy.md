# Redis TTL 策略

| 数据类型 | TTL | 过期行为 | 说明 |
|----------|-----|----------|------|
| 会话状态 | 3600s (1h) | 会话终止 | 用户活跃时自动续期 |
| QuerySpec | 随会话 | — | 随会话生命周期 |
| 执行计划缓存 | 1800s (30m) | 重新编译 | 计划可复用时命中 |
| Evidence 缓存 | 1800s (30m) | 重新检索 | 版本不变时可复用 |
| DAG 任务状态 | 随会话 | — | 长任务完成后可提前过期 |
| 检查点 | 随会话 | — | 状态机恢复依据 |
| 预算计数器 | 300s (5m) | 重置 | 防止单请求无限消耗 |
| 分布式锁 | 30s | 自动释放 | 防止死锁 |
| 幂等键 | 600s (10m) | 允许重试 | 防止重复执行 |
| Single Flight | 60s | 重新执行 | 去重窗口 |
| Embedding 缓存 | 86400s (24h) | 重新计算 | 文本不变时可复用 |
| 检索结果缓存 | 3600s (1h) | 重新检索 | 索引版本不变时可复用 |
| 限流计数 | 60s | 重置 | 滑动窗口 |

## 版本失效策略

知识库版本升级时（`index_epoch` 变更），以下缓存需批量失效:
- 执行计划缓存（`ace-rag:plan:*`）
- Evidence 缓存（`ace-rag:evidence:*`）
- 检索结果缓存（`ace-rag:cache:retrieval:*`）
- Embedding 缓存（`ace-rag:cache:embedding:*`）

使用 `SCAN + DEL` 或 Redis 6.0+ 的 `UNLINK` 异步删除。
