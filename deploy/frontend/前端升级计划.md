## 一、现状诊断

### 问题根因（API 字段与前端不匹配）

| 前端期望字段 | API 实际返回字段 | 后果 |
|-------------|-----------------|------|
| `c.doc_name` | `c.citation` / `c.source_doc` | 来源引用不显示 |
| `c.clause_number` | 包含在 `c.citation` 字符串内 | 条款号丢失 |
| `c.page` | 包含在 `c.citation` 字符串内 | 页码丢失 |
| `evidence_bundle.hits` | 不存在此字段 | 证据片段不显示 |
| `state_trace` 按 `:` 分割 | 实际为纯字符串数组 `["RECEIVED", ...]` | 流程面板解析错误 |

### API 实际返回结构

```
{
  request_id, session_id, answer,
  citations: [{index, citation, source_doc, chunk_id}],
  intent, complexity, is_refusal, refusal_reason,
  confidence, state_trace: ["RECEIVED", ...],
  evidence_count, sufficiency_score, latency_ms,
  claims_with_evidence, ambiguities
}
```

## 三、P0：前端问题追踪面板（已实施）

### 目标
用户每次提问后，右侧面板完整展示所有 API 返回信息，包括原始 JSON、流程轨迹、来源引用、关键指标、声明-证据映射，方便用户截图反馈问题。

### 实现内容
1. **原始 JSON 面板**：折叠展示完整 API 响应 JSON
2. **流程轨迹**：state_trace 可视化（每步带状态图标）
3. **来源引用列表**：正确解析 citations 数组，展示 citation + source_doc + chunk_id
4. **关键指标卡片**：意图/复杂度/证据数/充分性/置信度/延迟/拒答标志
5. **声明-证据映射**：展示 claims_with_evidence
6. **歧义信息**：展示 ambiguities
7. **复制/导出按钮**：一键复制原始 JSON 供反馈

## 四、P1-P2：修复显示问题（随 P0 一并实施）

### 来源引用修复
- 正确读取 `citations[].citation`（完整引用描述）
- 正确读取 `citations[].source_doc`（来源文档名）
- 正确读取 `citations[].chunk_id`（chunk 标识）

### 流程监控修复
- `state_trace` 直接遍历显示，不再按 `:` 分割
- 每步显示步骤名 + 序号 + 状态图标
- 底部汇总关键指标卡片

## 五、P3：数据库持久化对话（计划中）

### 技术方案
```
SQLite (agent_platform 已有 retrieval.db，可复用 SQLite 实例)
  └── conversations 表
      ├── id (UUID)
      ├── user_id (TEXT)
      ├── session_id (TEXT)
      ├── query (TEXT)
      ├── response (JSON)
      ├── created_at (TIMESTAMP)
      └── metadata (JSON)
```

### API 设计
```
POST   /api/v1/conversations          # 创建对话记录
GET    /api/v1/conversations           # 列出当前用户对话
GET    /api/v1/conversations/{id}      # 查看对话详情
DELETE /api/v1/conversations/{id}      # 删除对话
```

### 实现要点
- Agent 服务新增 `/api/v1/conversations` 路由
- 前端发送查询后自动保存到数据库
- 侧边栏从数据库加载会话历史
- 点击历史会话可恢复完整对话上下文

## 六、P4：用户区分与认证（计划中）

### 技术方案
- 简单方案：用户名 + 密码（JWT token）
- 前端登录页 → 后端验证 → 返回 JWT → 后续请求携带
- 每个用户只能看到自己的会话历史

### 数据模型
```
users 表: id, username, password_hash, role, created_at
conversations 表: 增加 user_id 外键
```

### 实现要点
- Agent 服务新增 `/api/v1/auth/login` 路由
- 前端增加登录页面
- 所有 API 请求携带 JWT token
- 管理员角色可查看所有用户对话
